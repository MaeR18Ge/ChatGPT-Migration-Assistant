# 实现与迁移经验

本项目使用 Windows PowerShell 5.1 承载 Windows Forms，数据操作由内嵌 C# 类型执行。所有界面均是本机程序，不依赖网页或网络 API。

## 从本次迁移提炼的关键处理

1. 应用名不代表进程用途。ChatCut 的 MCP 工具服务使用同一个 `ChatCut.exe`，必须结合命令行和窗口状态判断。
2. 在 GPT 中直接启动子进程不能保证它能在 GPT 退出后存活。后台操作与观察窗口必须通过 Windows 任务计划程序独立启动。
3. MSIX 应用的 Roaming／Local 路径可能被重定向。使用最终目录路径去重，并优先识别实际的包数据路径。
4. 文件权限的 DACL 与审计 SACL 分开处理，避免普通用户因缺少 `SeSecurityPrivilege` 失败。访问规则保持受保护／继承状态。
5. 只读 Git 索引等文件允许复制，但复制后直接设置时间会失败。先解除目标只读、设置时间，再恢复属性和权限。
6. GPT 退出不会停止 Codex 系统服务。需要查询保护锁的持有者，在具体服务有权限且属于已知名单时释放，并确保恢复。
7. 目标副本存在不代表迁移完成。只有内容校验、原路径切换、原路径验证及服务恢复后，才显示完成。
8. 保留原副本时，源盘空间并未立即全部释放。界面分别显示已清理字节数和保留字节数。

## 状态及事务

计划和日志属于当前用户，保存在私有目录。计划源目录必须仍符合当前用户的受支持发现规则，目标必须符合产品映射。日志中的副本路径必须精确匹配短名称派生规则。

单目录成功并不掩盖其他目录错误；任务最终状态可以是 `complete`、`partial_error`、`error` 或 `cancelled`。当前目录的 `copying`、`verifying`、`switching` 阶段分别记录。服务恢复意图先落盘，再发送停止命令。

Windows 任务不带重复触发器。每个任务的运行快照保留在任务目录，使恢复不依赖源工作目录当时是否可访问。

## 已知范围

- 不替代厂商的安装器、卸载器或正式数据目录设置。
- 已迁移目录只验证，不支持把一个现有链接再次改到第三个位置。
- 不自动处理云占位文件、嵌套链接、任意未知服务或任意自定义素材路径。
- 文件级测试覆盖模拟数据；不同应用版本的真实启动和升级仍需用户在保留副本状态下验证。
