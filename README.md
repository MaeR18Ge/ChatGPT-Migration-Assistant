# ChatGPT迁移助手

一个可以放在普通文件夹中运行的 **PowerShell 5.1 + Windows Forms** 桌面工具。支持识别并迁移 ChatGPT／Codex 与 ChatCut 的本地数据，保留原路径入口，不需要修改应用内部配置。

## 启动与分享

1. 把整个工具文件夹解压到本地磁盘。
2. 双击 `Start.vbs`，只显示程序窗口；如果 Windows 禁用了脚本宿主，使用 `Start.cmd`。
3. 选择目标盘或父目录，例如 `E:\`，点击“扫描 / 预检”。
4. 核对要迁移的目录和目标位置，点击“开始迁移”。
5. 保存工作并退出相应应用。观察独立进度窗口，完成后再打开应用检查项目、会话和设置。
6. 默认保留迁移前副本。确认软件正常后，在“历史 / 回滚 / 清理”中清理副本，才会释放这部分源盘空间。

分享时发送完整 ZIP 或完整工具文件夹，不能只发送快捷方式。程序不包含 API 密钥、用户会话或迁移数据。不是打包后的 EXE，不需要另外安装 Python、Node.js 或第三方 PowerShell 模块。

## 支持的目录

- ChatGPT：已识别的商店版浏览器数据、日志及文档输出；另支持常见普通安装版数据路径。
- Codex：用户数据目录、运行环境、后台组件、工作与输出目录。
- 可选共享技能：当前用户 `.agents\skills`，默认不选择；可能含其他工具的技能。
- ChatCut：项目、备份、预览、缓存、AI 助手数据、字体缓存、更新安装包。

目录根据当前 Windows 用户自动识别，目标下分别建立 `ChatGPT`、`Codex`、`ChatCut` 子目录。程序会通过最终物理路径合并 Windows 应用数据重定向产生的重复条目。

不移动 `WindowsApps` 主程序安装包、不迁移任意自定义素材盘。现有链接只提供验证，不能直接重定向到另一个新位置。支持清单未覆盖的应用版本需要先补充发现规则。

## 进程、锁和进度

- 不会自动结束有界面的应用，也不会把“没有窗口”一概认定为可以结束。
- ChatCut 的特定 MCP 连接服务会单独识别。只有命令行路径、程序位置、进程创建时间和无窗口条件均符合时，才按选项临时关闭。
- 需要退出的命令行、托盘和辅助进程会在进度窗口显示。
- 使用 Windows Restart Manager 查询 `.guard` 保护文件的锁持有者。只有已识别的 Codex 沙盒服务允许自动停止，且会记录恢复意图，在成功或失败时恢复。
- 未知后台锁会停止当前操作并保留原数据，不会强杀未知进程。
- 后台迁移与进度窗口由 **当前用户的一次性 Windows 任务**启动，没有周期触发器。关闭 GPT、主窗口或进度窗口不会取消后台迁移。
- 总体进度按目录计数；文件进度只表示当前目录的复制／校验进度，不冒充总数据量百分比。

## 数据保护与恢复

每个目录按以下顺序处理：复制 → SHA256 逐文件核对及目录结构检查 → 原目录暂存 → 建立目录联接 → 再次验证原路径访问 → 按选项保留或清理原副本。

只读文件会临时解除目标副本的只读属性以写入时间戳，再恢复属性。访问控制规则按 DACL 保留，不请求系统审计权限；新目标根目录只授予当前用户、管理员和 SYSTEM，必要时保留原有 Codex 沙盒读取权限。支持 Windows 长路径。

目标非空且不属于本任务、路径互相包含、异常链接、嵌套链接或云占位文件会被拒绝。原路径链接删除采用非递归方式；不会沿链接递归删除目标盘数据。

“安全停止”在复制、验证、等待等安全点生效。路径切换和清理过程中不可立即中断。中断后可在历史任务中继续；切换途中缺失原路径时，会利用事务记录恢复。未完成目标副本会在目标旁保留为 `.incomplete-...`，不混入下一次复制。

相同源目录或目标目录有互斥锁，不能被多个任务同时操作。

“回滚最新数据”会等待应用退出，将目标盘最新内容重新复制并验证到原位置，再移除链接。它不直接恢复陈旧备份，也不会删除目标盘的内容。原盘需要有足够空间。

## 日志与历史任务

默认位置：`%LOCALAPPDATA%\ChatGPTtMigration\runs\<任务ID>`。

- `plan.json`：明确的源、目标、选项和预计大小。
- `journal.json`：每个目录的事务阶段、备份路径和服务恢复记录。
- `status.json`：以原子方式更新的实时状态。
- `events.log`：阶段及错误记录。
- `engine`：该任务启动时保存的程序快照。即使工具本身位于待迁移的工作目录中，也能继续运行。

历史任务可以重新打开进度、继续迁移、回滚、清理原副本和导出诊断 ZIP。诊断包含目录路径和错误详情，不包含迁移文件正文。不要手工修改计划或事务日志。

任务记录保留是为了恢复和回滚。已完成的一次性任务不会自动再次执行。

## 权限与环境

支持 Windows 10／11、Windows PowerShell **5.1**、Windows Forms 和固定本地 NTFS 磁盘。Windows Task Scheduler 服务必须可用，企业策略不得禁止当前用户创建任务。

普通用户通常可以迁移自己的文件。若停止持锁服务的权限不足，界面会明确报错。可以使用同一 Windows 账户以管理员身份运行 `Start.cmd` 后重试；已经提升的主界面会为后台任务采用相同权限级别。程序不会自行弹出 UAC 或尝试绕过组织策略。

源数据位于加密文件夹、特殊云同步目录、嵌套链接或高度定制权限环境时，不保证可以自动迁移。应按错误提示保留原文件并处理，不应直接删除原路径。

## 开发与验证

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\tests\Integration.ps1
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\src\Main.ps1 -SelfTest
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```

集成测试仅使用项目 `work` 下生成的临时夹具和模拟发现规则，不迁移真实应用目录，不停止真实应用或服务。会短暂创建并删除一个独立任务作为调度器测试。失败夹具保留用于排查；成功测试清理夹具。结果写到 `dist\test-results.json`。

源代码：`src\Native.cs` 为长路径、复制、校验、权限和锁查询；`Migration.Core.psm1` 为发现、计划及独立任务；`Worker.ps1` 为事务执行；`Main.ps1`、`Progress.ps1`、`UI.psm1` 为界面。
